| Term | Definition |
| --- | --- |
| Aelium | Organization using Qualitas defaults for this CRM's quality governance documents. |
| CRM | Internal system centered on managing customers and prospective customers, with contracts, invoices, incidents, tags, search, and business-specific service modules such as API assets. |
| Customer | Company with an active signed contract with Aelium. |
| Prospective customer | Company contacted or evaluated by Aelium but without a signed contract. |
| CIF | Company tax identifier used by the CRM as a customer or prospect identifier. |
| API template | Reusable API model that can be recommended or related to customers and prospects. |
| Specific API | API designed or implemented for a particular customer. |
| Service module | A business-specific CRM area that extends customer management for a concrete service domain; API templates and specific APIs are the first example in this project. |
| Tag | Reusable label used to classify and filter CRM records, commonly searched with the `#tag` convention. |
| Keycloak | Planned production identity provider for CRM user authentication, role/group management, and token validation. |
| Local auth baseline | Current development authentication approach based on seeded users, encrypted stored passwords, and in-memory session tokens. |
| Work Package | Planning unit that realizes one or more functional or non-functional requirements. |
| Evidence | Immutable or reviewable proof that a planned test was executed and what result it produced. |
